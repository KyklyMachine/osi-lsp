# Спецификация Protocol Language (Protocol Lang)

Этот документ описывает синтаксис, структуру и возможности языка Protocol Language, а также архитектуру его поддержки в VS Code через Language Server Protocol (LSP).

## 1. Общая структура

Программа на Protocol Language представляет собой последовательность инструкций (statements), выполняемых сверху вниз. Ранее язык использовал структуру блоков (Handlers `## NAME`), но в текущей реализации поддерживается плоская структура кода (список инструкций).

### Комментарии
Комментарии начинаются с символа `;` и продолжаются до конца строки.
```protocol
; Это комментарий
declare integer ; Объявление переменной
```

## 2. Типы данных и Переменные

Язык поддерживает строгую типизацию при объявлении переменных.

### Объявление
Синтаксис: `ИМЯ declare ТИП`
Поддерживаемые типы:
*   `integer` - Целые числа
*   `buffer` - Буферы данных (массивы байт)
*   `string` - Строки
*   `queue` - Очереди

**Пример:**
```protocol
counter declare integer
my_buffer declare buffer
message declare string
msg_queue declare queue
```

### Использование переменных
В выражениях переменные обычно используются с префиксом `$`, но в некоторых командах присваивания (`varset`, `timer`) допускается использование имени без префикса.

## 3. Операторы и Команды

### Присваивание (`varset`)
Синтаксис: `ВЫРАЖЕНИЕ varset ПЕРЕМЕННАЯ`
```protocol
0 varset $counter
$counter + 1 varset counter  ; Можно без $ в целевой переменной
```

### Работа с буферами (`bufferit` / `unbufferit`)
Упаковка данных в буфер и распаковка из него.

**Упаковка (`bufferit`):**
Синтаксис: `БУФЕР bufferit ОБЩАЯ_ДЛИНА ЗНАЧЕНИЕ1 ДЛИНА1 ЗНАЧЕНИЕ2 ДЛИНА2 ...`
```protocol
; Записать в buff 2 байта (число 1) и 4 байта (число 500)
buff bufferit 6 1 2 500 4
```

**Распаковка (`unbufferit`):**
Синтаксис: `unbufferit БУФЕР ПЕРЕМЕННАЯ1 ДЛИНА1 ПЕРЕМЕННАЯ2 ДЛИНА2 ...`
```protocol
unbufferit $buff type 1 value 4
```

### Управление потоком (`goto`, `if`, `subprog`)

**Метки:**
Определяются как `ИмяМетки:`.

**Безусловный переход:**
Синтаксис: `goto МЕТКА`

**Условный переход:**
Синтаксис: `УСЛОВИЕ if МЕТКА`
```protocol
$counter > 10 if EndLoop
goto Loop
EndLoop:
```

**Подпрограммы:**
*   Определение: `substart ИМЯ ... subend`
*   Вызов: `subprog ИМЯ`
*   Возврат: `return` (используется внутри подпрограммы или хендлера)

```protocol
subprog MyCalc

substart MyCalc
    10 varset $res
subend
```

### Таймеры (`timer` / `untimer`)

**Запуск таймера:**
Синтаксис: `СОБЫТИЕ timer ПЕРЕМЕННАЯ_ТАЙМЕРА ЗАДЕРЖКА [ПАРАМЕТР ЗНАЧЕНИЕ ...]`
```protocol
TIMEOUT_EVENT timer my_timer 5000 correlation_id $id
```

**Отмена таймера:**
Синтаксис: `untimer ID_ТАЙМЕРА`

### Очереди (`queue` / `clearqueue`)

**Добавление в очередь:**
Синтаксис: `queue ИМЯ_ОЧЕРЕДИ ЗНАЧЕНИЕ`

**Очистка очереди:**
Синтаксис: `clearqueue ИМЯ_ОЧЕРЕДИ`

### События (`generateup` / `eventdown`)
Генерация событий вверх или вниз по стеку протоколов.
Синтаксис: `ИМЯ.СОБЫТИЯ generateup [ПАРАМЕТР ЗНАЧЕНИЕ ...]`
Синтаксис: `ИМЯ.СОБЫТИЯ eventdown [ПАРАМЕТР ЗНАЧЕНИЕ ...]`

### Отладка (`out`)
Вывод значений.
Синтаксис: `out ВЫРАЖЕНИЕ`

### Строковые операции (`delete`)
Удаление части строки.
Синтаксис: `delete ПЕРЕМЕННАЯ НАЧАЛО ДЛИНА`

### Расчет CRC (`calccrc`)
Синтаксис: `calccrc РЕЗУЛЬТАТ БУФЕР`

## 4. Выражения

Поддерживаются сложные выражения с приоритетом операций.

*   **Арифметика:** `+`, `-`, `*`, `/`, `%`
*   **Сравнение:** `==`, `!=`, `>`, `<`, `>=`, `<=`
*   **Логика:** `&&`, `||`
*   **Литералы:**
    *   Числа: `123`, `-10`
    *   Строки: `"text\n"`
    *   Коды символов: `#0`, `#255`
*   **Группировка:** `( )`

### Встроенные функции
Могут использоваться внутри выражений:
*   `sizeof($var)`
*   `copy($str, start, len)`
*   `pos($str, substr)`
*   `dequeue($q)`
*   `peek($q)`
*   `qcount($q)`
*   `locguide($val)`
*   `CurrentSystemName()`

## 5. Архитектура обработки (Language Server)

Реализация выполнена на Python с использованием библиотеки `pygls`.

### Компоненты:

1.  **Lexer (`lexer.py`)**:
    *   Разбивает исходный текст на токены (ключевые слова, идентификаторы, литералы).
    *   Обрабатывает специфичные токены, такие как `##`, `$var`, `#char`.

2.  **Parser (`parser.py`)**:
    *   Рекурсивный нисходящий парсер (Recursive Descent Parser).
    *   Строит AST (Abstract Syntax Tree) - дерево объектов (`ast_nodes.py`).
    *   Поддерживает восстановление после ошибок (частично) и генерацию `ProtocolError` с точным указанием места ошибки.

3.  **Semantic Analyzer (`semantic_analyzer.py`)**:
    *   Проходит по AST (Visitor Pattern).
    *   Строит таблицу символов (`SymbolTable`).
    *   **Валидация:**
        *   Проверка объявления переменных перед использованием.
        *   Проверка повторного объявления.
        *   Проверка существования меток (`goto`) и подпрограмм.
        *   Проверка типов (базовая).
        *   Поиск неиспользуемых переменных, меток и подпрограмм (Warnings).

4.  **Language Server (`server.py`)**:
    *   Обеспечивает связь с VS Code по протоколу LSP.
    *   Запускает валидацию (`textDocument/didChange`, `didOpen`).
    *   Публикует диагностики (ошибки и предупреждения) в редактор.
    *   (В планах/частично): Autocomplete, Go to Definition, Hover.

### Особенности реализации:
*   **Expression Statement:** Вызовы функций или одиночные выражения могут быть самостоятельными инструкциями.
*   **Loose Typing in Parser:** Парсер допускает использование идентификаторов вместо переменных (`VARIABLE`) в командах `varset` и `timer` для гибкости.
